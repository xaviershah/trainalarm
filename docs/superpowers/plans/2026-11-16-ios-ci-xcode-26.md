# iOS CI: select Xcode 26 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the iOS CI job build and test the app again. It has failed on every run since the AlarmKit merge (Stage 3, PR #9): the `macos-15` runner's default Xcode is 16.4, which has no iOS 26 SDK, so `AlarmKitClient.swift` fails with `no such module 'AlarmKit'`.

**Architecture:** One extra step in `.github/workflows/ios.yml` selects an Xcode that ships the iOS 26 SDK before anything builds. Nothing else changes.

**Tech Stack:** GitHub Actions, `macos-15-arm64` runner image (version 20261104.0514 at the time of writing), XcodeGen, `xcodebuild`.

**Evidence (checked, not assumed):**
- Failing runs on `main`: #9 merge (run 43213404409) and #11 merge (run 43457121808), and on PR #12 (run 43483202774): all `ios/Sources/TrainAlarm/Alarm/AlarmKitClient.swift:1:8: error: no such module 'AlarmKit'`. The last green iOS CI on `main` was the Stage 2 merge (8 Oct).
- The runner image readme (`actions/runner-images`, `images/macos/macos-15-arm64-Readme.md`) lists Xcode 26.3, 26.2, 26.1.1 and 26.0.1 installed at `/Applications/Xcode_26.3.app` etc., with 16.4 as the default; the iOS 26.0, 26.1 and 26.2 SDKs and simulators are installed (Xcode 26.3 uses the iOS 26.2 SDK).
- The project's deployment target is iOS 26.0 (`ios/project.yml`); it is built and tested locally with Xcode 26.5.

### Task 1: Select Xcode 26.3 in the iOS workflow

**Files:**
- Modify: `.github/workflows/ios.yml`
- Modify: `.ai/testing-guide.md` (one line)

- [ ] **Step 1: Add the step**

In `.github/workflows/ios.yml`, directly after the `actions/checkout@v4` step and before `Install XcodeGen`, add:

```yaml
      - name: Select Xcode 26.3 (AlarmKit needs the iOS 26 SDK; the runner default is Xcode 16.4)
        run: sudo xcode-select -s /Applications/Xcode_26.3.app
      - name: Show the Xcode and SDK in use
        run: |
          xcodebuild -version
          xcrun --show-sdk-version --sdk iphonesimulator
```

The working directory default for the job is `ios`; these steps do not depend on it.

- [ ] **Step 2: Note it in the testing guide**

In `.ai/testing-guide.md`, find the sentence that says CI runs the same iOS tests on every push/PR (under "Run it (needs full Xcode 26; CI runs ...)") and add: `CI selects Xcode 26.3 explicitly, because the macos-15 runner's default Xcode (16.4) has no iOS 26 SDK.`
